# SOW 2.g — U-Boot environment round-trip from Linux (2026-09-08)

Board ZCU102 #2. Host `bxqp8b3-ub22`. Session 16:15Z–17:45Z.

## Result

Bidirectional U-Boot environment access demonstrated on hardware.

| direction | evidence |
|---|---|
| U-Boot -> Linux | `setenv msu2_marker uboot_20260908` + `saveenv` at prompt; `fw_printenv msu2_marker` returned it after a power cycle |
| Linux -> U-Boot | `fw_setenv msu2_linux_marker linux_20260908_1738`; U-Boot `printenv` returned it after a power cycle |

U-Boot reported `Loading Environment from FAT... OK` on the boot following the
Linux write. Two boots earlier the same U-Boot reported
`*** Error - No Valid Environment Area found`. U-Boot therefore accepted an
environment written by libubootenv as valid: CRC, flag byte and redundancy
scheme agreed across two independent implementations.

`fw_printenv` with no argument returned 75 variables. Both markers were present
at the U-Boot prompt afterward, so the Linux write merged rather than replaced.

## Redundancy behaviour — measured

Baseline before `fw_setenv`, captured host-side from the unmounted card:

    uboot.env         262144  9afabc88dbd465d121decc96433cf518
    uboot-redund.env  262144  5b2408144a8ad75e827feae14fdf4290

After `fw_setenv` + `sync`, read on the board:

    uboot.env         9afabc88dbd465d121decc96433cf518   UNCHANGED
    uboot-redund.env  5c78f16778e05b1c75d858b4569e9e3a   CHANGED

Exactly one copy was written. The primary was left intact, which is the
interrupt-safe update mechanism SOW 2.g asks for.

## Correction to the project record

Prior notes state that `saveenv` creates `uboot-redund.env` as ONE file and
NOT a primary/redundant pair. That is wrong. `fatls mmc 0:1` after `saveenv`
on this board shows BOTH:

    262144   uboot-redund.env
    262144   uboot.env

`/etc/fw_env.config` consequently needs two lines, one per copy. A single-line
config would not describe this environment correctly.

## Environment absent on this card

Before this session the card carried no environment at all. Host-side `ls` and
`md5sum` both failed on `uboot-redund.env`, and the boot log showed
`*** Error - No Valid Environment Area found`. The previously recorded U-Boot
`saveenv` work was done on different media. The pair on this card was created
this session and observed, not inherited.

## Dependency closure

`fw_printenv` needs two libraries not present in the INITRD rootfs. The
closure was established by reading `readelf -d` on each artifact in turn, after
two failures caused by checking only the executable's direct dependencies.

    fw_printenv           -> libubootenv.so.0, libc.so.6, ld-linux-aarch64.so.1
    libubootenv.so.0.3.5  -> libz.so.1, libyaml.so.0.2, libc.so.6
    libyaml.so.0.2.5      -> libc.so.6                              (terminal)

`libz.so.1` (1.3.1) is already on the board. `libubootenv` and `libyaml` were
built and carried over.

Max GLIBC symbol version required by `fw_printenv` is 2.34; board glibc is 2.39.

## DELIBERATELY NOT CLAIMED

- **Not a provisioned appliance.** The rootfs is INITRD. `/tmp/fw`,
  `/etc/fw_env.config` and the symlinks did not survive the power cycle and do
  not exist now. This is a demonstration. Provisioning means adding
  `libubootenv-bin` to the rootfs and rebuilding the image.
- **Recovery was not tested.** Which copy gets written was measured. Deliberate
  corruption of one copy followed by a U-Boot fallback was not attempted.
- **No verified boot.** `CONFIG_FIT_SIGNATURE` remains unset. The verification
  leg of 2.g is untouched.
- **Autoboot delay is zero.** Reaching the U-Boot prompt depends on a keypress
  landing in a zero-second window. Not a reliable procedure for a demo.
- The post-write `uboot-redund.env` (`5c78f167...`) exists only on the SD card.
  Only the pre-write pair is committed.
