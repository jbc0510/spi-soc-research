# Task 2e target access status — 2026-10-16

The ZCU102 is reachable through the CP2108 UART and remains responsive at the `newQspi` console. Root-level read-only preflight confirmed Linux `6.12.10-xilinx-g0a0f70e531c7`, PetaLinux 2025.1, FPGA Manager state `operating`, the validated bitstream hash, `/dev/spidev1.0`, platform device `a0000000.spi`, SPI child `spi1.0`, a 1 MiB spidev buffer, and an active AXI SPI IRQ. See `target_preflight.log`.

PL0 is reported by the Linux clock framework at 99,990,000 Hz and the CPU governor was `userspace` at 1,200,000 kHz during preflight. The current measured SPI `speed_hz` readback was 1,000,000 Hz; physical SCK was not measured. The SPI node is `0600 root:root`, so the `petalinux` console account cannot run the transfer directly. Authenticated sudo was used for the controlled operation.

The Linux AArch64 runner was uploaded using a shell `printf` escape receiver because target BusyBox lacks `base64`. Its staged SHA-256 matched the host-built runner (`36f60c0d6584a654aa3cf5383359a37e084cc599b678b51bf7c59438e6b31ded`). The guarded one-second test used `/dev/spidev1.0`, mode 0, 8-bit words, 64-byte payloads, 1 MHz requested/read-back speed, and a host-side UART watchdog. It completed 15,354 transfers and verified 982,656 payload bytes (0.9826 application MB/s), with zero API errors, zero mismatches, and a maximum transfer call of 130.833 µs. Raw output is in `target_smoke_attempt.log`.

This is direct evidence that the Linux spidev path transferred data through the J55 loopback without a reported mismatch during this short smoke. It is not a sustained throughput result. The comparison plan still requires measured physical SCK, paired 60-second runs for all 11 payload sizes and three repetitions on Linux and bare metal, a paired run manifest, and target-side bare-metal execution. The Linux SPI ioctl itself has no userspace deadline; the short test was monitored by a host-side serial watchdog.

Subsequently, all 33 Linux sustained points completed at 49.995 MHz requested/read-back speed, with 11 payload sizes × three repetitions × at least 60 seconds. Every point completed with zero API errors and zero mismatches. Per-point throughput and CPU values are in `linux_sustained_runs.csv`; medians are in `linux_sustained_medians.csv`; the machine-readable configuration and artifact hashes are in `linux_sustained_manifest.json`. Original UART captures are in `linux_sustained_serial_raw.tar.gz`. The operating point (userspace governor, 1,200,000 kHz) was read before the sustained set but not sampled per point, and the approximately 51 MHz J55 measurement comes from September 29 rather than a simultaneous measurement.

After those runs were safely captured and pushed, Linux was gracefully powered down to prepare a JTAG bare-metal run. XSCT then reported the A53 FPD as unpowered. Standard JTAG reset attempts did not restore the processor target, and the final XSCT probe reported a closed TCF channel. No FPGA, SD-card, or boot-image writes were made. The detailed recovery record is `baremetal_jtag_recovery_attempt.log`; the board needs a physical power-on/reset before bare-metal execution can proceed.
